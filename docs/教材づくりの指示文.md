# 新しい資格の教材づくり（ひな形）

第二級陸上特殊無線技士（二陸特）の教材を作ったときの指示文を、ほかの資格でも使える形にしたものです（2026年10月20日）。
アマチュア無線4級など、新しい資格を増やすときに使います。

## 全体の流れ

1. **教材をつくる**：下の「1. 教材づくりの指示文」の【　】を書きかえて、Claude Code の**別のチャット**に貼る。
   教材は資格対策フォルダの中にできる（アプリのフォルダにはさわらない）。
2. **アプリに資格を登録する**：手帳 → 資格で登録。「冒険の世界」は「この資格だけの世界」にする。
3. **問題集を取り込む**：問題タブ →「CSV・写真から追加」で、問題集のCSVをまとめて選び、「紐付ける資格」を新しい資格にする。
4. **アプリ側の仕上げ**：このリポジトリの Claude Code に「○○の教材を取り込んで」と頼む（下の「3. アプリ側でやること」）。
5. **世界の地図の絵**：下の「2. 世界の地図の絵の指示文」を ChatGPT に貼って、絵をつくる。できたら `イラスト` フォルダに入れて、Claude Code に「地図を入れて」と頼む。

## 1. 教材づくりの指示文（別のチャットに貼る）

【資格名】【略称】【フォルダ名】を書きかえて使います。

```text
# 依頼：【資格名】（【略称】）の学習教材を作ってください

私はプログラミング初心者です。説明は日本語で、専門用語はかみ砕いてください。
作った教材は、私の個人用学習アプリ「Study Quest」（別の場所にあるアプリ）に、あとで取り込みます。
このチャットでは教材のファイルだけを作り、アプリのフォルダ（C:\Users\uto\studyquest-vite）には一切さわらないでください。

## 置き場所
C:\Users\uto\OneDrive\Desktop\資格対策\【フォルダ名】\ の中に作ってください（なければ作る）。
- 問題集\  ……… 問題のCSV
- 参考書\  ……… 参考書のデータ
- README.md …… 作ったファイルの一覧・問題数・確かめた方法・自信のない所

## 進め方
1. まず試験の実施団体の公式の案内で、いまの試験科目・問題数・出題形式（選択肢の数など）・試験時間・合格の基準・電卓の扱いを確かめ、README の最初に「本番の形」の表として書いてください（出典のURLも）。
2. 科目を分野に分けた「目次」を作り、私に見せて確認を取ってから、問題を作り始めてください。
3. 分野ごとに少しずつ作り、できたものから README に追記してください。

## 1. 問題集（CSV）の形（いちばん大事）
- 1ファイル＝問題集1つ。ファイル名がそのまま問題集の名前になります。
  例：「【略称】_法規_01_〇〇.csv」「【略称】_工学_03_〇〇.csv」（科目の名前をファイル名に入れてください。アプリが科目＝地域を分けるのに使います）
- 文字コードは UTF-8（BOM付き）、区切りはカンマ。
- 1行目は見出しで「問題,解答」の2列だけ。3列目以降は読まれません。
- 問題文の先頭に、重ならない番号を付けてください。例：「【略称】法規-0101 」
- 問題の種類は次の2つ。1問の中で迷わない形にしてください。
  - ○×問題：問題は言い切りの文。答えは必ず「○」か「×」で始める。
    例）答え「×　正しくは…【解説】…【根拠】〇〇法第〇条」
  - 選択問題：問題文の最後に、選択肢を (1)〜(4) のように並べる（選択肢の数は本番に合わせる）。
    答えは必ず「答：(3)」の形で始め、続けて【解説】と【根拠】。
    （この形にすると、アプリで番号をタップして答えられます。問題文の途中に (1) などの番号を使うときは、①②③ にしてください）
- 答えの中の書き方：【解説】は1〜3文で、なぜそうなるかがわかるように。【根拠】は法令の条文（例「〇〇法第4条」）か、公式・考え方。
- 計算問題は、答えに計算の途中も短く書いてください。電卓が使えない試験なら、暗算・筆算でできる数字にしてください。
- ひっかけ（数字・期間・「〜しなければならない／できる」など）を入れた○×問題も、正しい文と同じくらいの数を作ってください。
- 過去問の文章をそのまま大量に写すのではなく、出題範囲に沿って作ったオリジナルの問題を中心にしてください。

## 2. 正しさのルール
- 法令は、e-Gov法令検索（https://laws.e-gov.go.jp/）の現在の条文で必ず確かめてください。
  数字・期間・用語は条文どおりにし、【根拠】に法令名＋条番号を書いてください（例「〇〇法施行規則第3条第1項」）。
- 計算はすべて自分で検算してください（単位も確かめる）。
- 確かめられなかった問題・自信のない問題は作らないか、README の「要確認」に一覧で書いてください。推測で埋めないでください。

## 3. 参考書のデータ（暗記用の表）
私のアプリには「参考書」という画面があり、次の形のデータで章を表示します（表で読む・答えの欄を隠して覚える・クイズ）。
参考書\【略称の英字】_sankosho.js に、この形で書いてください（JavaScript。export するのは配列1つ）。

export const 【略称の英字・大文字】_SUBJECTS = [
  {
    id: "【略称の英字】-hoki",          // 半角英字
    name: "【略称】 法規",
    chapters: [
      {
        id: "teigi",                    // 章ごとに重ならない半角英字
        title: "〇〇の目的と定義",
        intro: "この章で覚えることを1〜2文で。",
        cols: ["項目", "内容"],          // 表の列名。1列目が見出しの列
        ask: [1],                       // クイズで聞く列の番号（0始まり。1列目は聞かない）
        rows: [
          { c: ["〇〇", "…"], ref: "〇〇法第1条" },   // c＝各列の中身、ref＝根拠の条文（法令でない科目は ""）
        ],
        tip: "覚え方のコツを1文で（なくてもよい）",
      },
    ],
  },
];

- 1つの章は5〜15行くらい。同じ列には同じ種類の中身を並べてください（クイズで、ほかの行の値を選択肢に使うため）。
- ref は「〇〇法第4条」「〇〇法施行規則第3条第1項」のように、法令名＋条番号で書いてください。
- 中身は問題集と同じく、条文で確かめたものだけにしてください。

## 4. 最後に README.md へ書くこと
- 本番の形（科目ごとの問題数・試験時間・合格の基準・出題形式・電卓の扱い。確かめた出典つき）
- ファイルの一覧（ファイル名・問題数・○×と選択の内訳）
- 参考書の章の一覧
- 使った法令の一覧（法令名・e-Gov の法令ID・確かめた日）
- 構成の順番を問う問題があれば、その並び順の一覧（例：受信機の各部の順）
- 要確認の一覧
```

## 2. 世界の地図の絵の指示文（ChatGPT に貼る）

【世界の名前】【地域1】【地域2】【魔王城の名前】【モチーフ】を書きかえて使います。
今までの地図（`public/art/storymap.webp`・`storymap-radio.webp`）とキャラクターの絵を2〜3枚添付すると、絵柄がそろいます。

```text
# 依頼：学習RPGアプリ「Study Quest」の新しい世界の地図イラスト

資格試験の勉強をRPGにした、私の個人用アプリの絵です。
添付した絵（以前作ってもらった地図・キャラクター）と同じ絵柄・同じ色合いでお願いします。

## アプリの世界観
- 資格ごとに「世界」が分かれていて、主人公は全部の世界で同じ。
- 主人公：ルナ（白銀の長い髪、青い瞳、白・紺・金の衣装の魔法剣士）。仲間：カイト（黒髪の少年）、セレナ（金髪の少女）、レイヴン
- 絵柄：明るいアニメ調ファンタジー。白・金・青が基調。きらきらした光、透明感のある空

## 新しい世界のコンセプト
- 世界の名前：「【世界の名前】」（【資格名】の世界）
- 【モチーフ】をファンタジーの中に自然に混ぜる
- 地域は2つ：
  1. 「【地域1】」：〇〇な場所（どんな建物・景色か）
  2. 「【地域2】」：〇〇な場所
- ゴール：「【魔王城の名前】」（この世界の魔王城）。いちばん上（奥）に立つ城

## 地図の条件（いちばん大事）
- 横長（16:9）、真上から少し斜めに見下ろした、全体が見渡せる地図
- いちばん手前（下の中央）に出発地の町、いちばん奥（上の中央）に魔王城
- 下から上へ道がつながる。途中で左の道（【地域1】）と右の道（【地域2】）に分かれ、最後に中央で合流して魔王城へ向かう
- 道沿いに、クエストの場所になる目印（小さな広場・塔・橋・祠など）を20〜25か所くらい、間隔をあけて置く
- 文字・数字・題名・看板の文字・UIの枠はできるだけ入れない（あとでアプリ側で印や名前を重ねるため）
- キャラクターは入れないか、入れるなら小さく
- 画面の端まで絵で埋める（白い余白や枠をつけない）
```

## 3. アプリ側でやること（このリポジトリの Claude Code に頼む）

教材ができたら、次のことをする（二陸特のときと同じ）。

| やること | 場所 |
|---|---|
| 教材の点検（CSV の形・4択の形・根拠の条文が実在するか） | 資格対策フォルダ |
| 条文データの追加（法令を足して取り直す） | `scripts/fetch-laws.mjs` の `LAW_SOURCES`、App.jsx の `LAWS`（略称の aliases も） |
| 法令名のない「第1条」をどの法令とみなすか | App.jsx の `RADIO_LAW_RE` のような正規表現（その資格の法令名） |
| 参考書の追加 | `src/data/sankosho-〇〇.js` を置き、App.jsx の `SANKO_GROUPS` に足す |
| 世界の設定 | `src/data/worlds.js` の `WORLD_PRESETS` に、名前で合う資格の設定を足す（name・sub・castle・boss・icon・regions［科目ごとの地域・色・守護者・紋章・戦いの背景・物語 arc］・chapters・exam［本番の形］・drills） |
| 本番の形 | worlds.js の exam（科目ごとの問題数 n・合格に必要な数 pass・時間 minutes・1問の点 points・勘で当たる確率 guess）。README の「本番の形」から |
| 地図の絵 | 絵を public/art/ に置き、worlds.js の map（file・box・nodes・order・fog・start）。nodes は絵に描かれた印の位置 |
| 周回の部屋の見出しの絵（あれば） | App.jsx の LapRoom（`isRadioQual` のような判定で切り替え） |

worlds.js に設定を足さなくても、資格を登録して問題集を紐付ければ「（資格名）の世界」ができ、地域はフォルダごとに「（フォルダ名）の地」になる。
